# StockCount V1 测试与验收计划

**状态：可执行验收规格草案；并不表示测试已经执行。** 2026-11-23。

## 1. 分层测试策略

- **Core Unit（纯内存）**：扫码状态机、状态判断、数量校验、长度、同单去重策略、生产写保护。
- **Contracts/API（Mock repository）**：DTO 序列化、环境切换、分页和排序、错误码与 Problem Details。
- **Infrastructure Read-only（需数据库权限）**：分别连接 COB/XTEST 验证真实字段、列表、标签/物料关系和库位。
- **XTEST Write Integration（须授权）**：隔离/可清理测试单，验证实际 X3 写入、幂等/并发、审计字段、状态规则；只用测试 Schema。
- **Device/E2E（真机）**：实际工业 PDA 扫码广播、旋转/后台/输入法、用户连续操作、网络中断恢复。
- **Production Gate**：正式只读验收 → 业务审批 → 配置启用正式写 → 限量监控/回滚。

## 2. P0 验收矩阵

| ID | 测试场景 | 预期 |
| --- | --- | --- |
| T-01 | 首次安装/启动 | **没有登录**，可选/默认 Test 并进入列表 |
| T-02 | Test 列表 | 所有测试盘点单可经分页查询，包含状态码0/1等 |
| T-03 | Production 列表 | 返回 COB 的现存单据，不混入 XTEST |
| T-04 | Test→Production 切换 | 旧环境选单/库位/箱草稿不串到新环境；结果未知请求保留原环境追踪 |
| T-05 | 非法环境字符串/Schema 名 | API 返回 400，不能任意查询其他 Schema |
| T-06 | 列表状态不同 | **所有状态都可见**，没有隐式状态过滤 |
| T-07 | 未选择盘点单 | 不允许扫库位以外的作业、不能提交 |
| T-08 | 未扫库位直接扫箱 | 提示「请先扫描盘点库位！」且不回填箱 |
| T-09 | 扫相同库位/切库位 | 同值不变；不同库位替换；未保存草稿需确认 |
| T-10 | 库位无效/不属仓库 | 后端拒绝、保留原库位；不杜撰 `LC` 规则 |
| T-11 | 有效箱 QR | 返回 PID、产品、品名、规格、批次、STU |
| T-12 | 标签 STA=1/4/7/8/9 | **仅状态不同不影响盘点准入**；不得返回 LABEL_STATUS_FORBIDDEN |
| T-13 | 空/未知/重复标签匹配 | 显示明确错误、无旧箱内容 |
| T-14 | 标签当前数/QR QT 与实盘不同 | 用户手填99，标签/二维码100；服务端最终保存 `QTYSTU_0=99` |
| T-15 | 实盘数量为空 | 不允许提交；其它边界待业务定值 |
| T-16 | 箱码长度21+ 或库位长度11+ | 不截断；明确拒绝不能安全落库的值 |
| T-17 | 盘点单 `CUNSTA_0=0` | 后端业务规则允许作业（前提生产开关已授权）；其他状态待确认 |
| T-18 | 业务同单同箱重复 | 按最终批准规则提示且不造成意外新增；跨单行为独立 |
| T-19 | 同请求 ID 重试 | 最多一次持久化，后续返回原结果 |
| T-20 | 同请求 ID 不同载荷 | 409 冲突，不写第二份 |
| T-21 | 两台 PDA 并发同单同箱 | 不出现超出业务允许的重复记录 |
| T-22 | 保存时双击/重扫 | 不重复提交、不覆盖用户输入 |
| T-23 | API 超时/结果不明 | 不清箱/数，保留原 `RequestId`；能安全查状态 |
| T-24 | 保存失败 | 不丢失盘点单/库位/当前箱/数量；可恢复 |
| T-25 | 保存成功 | 弹出「提交成功！」约一秒后自动收起，仅清当前箱数据 |
| T-26 | 无创建/关单入口 | V1 无创建、关闭、ERP 调整操作 |
| T-27 | 正式写入默认禁用 | 后端返回 403 PRODUCTION_WRITE_DISABLED；仍允许正式只读 |
| T-28 | 真机扫描广播 | 接收正确二维码，数字框不会被扫描内容覆盖，后台恢复无重复 Receiver |
| T-29 | 数据类型一致性 | `CUNTYP_0` 用 string；跨 Schema 不发生 INT1 溢出；数量用 decimal |
| T-30 | 公开仓库泄露扫描 | 不包含连接字符串、私钥、生产原始明细与设备内部网络地址 |

## 3. 核心测试数据（必须为合成）

- 单据 `COUNT-DEMO-001`：状态0、站点A01、仓库WH01。
- 标签 `BOX-DEMO-01`：`STA_0=9`、二维码QT100、标签当前数量100，测试人工填入99可提交。
- 标签 `BOX-DEMO-02`：`STA_0=4`，确认不按状态拒绝。
- 库位 `LOC-DEMO01`：10字符，边界长度；另设11字符来测试失败。
- 用 XTEST 隔离交易或 Mock 替代真实 X3 数据；**不要往真实测试帐套写入这些假数据，除非明确授权创建/清理测试数据**。

## 4. 完成定义 (Definition of Done)

- 所有 P0 测试通过并有命令、报告或操作录像/截图（敏感信息脱敏）。
- 业务签字确认其它单据状态的提交准入、数量边界、同箱复盘、PCU/STU 换算和库位规则。
- 实际 X3 写入能完整处理 ROWID/AUUID/UPDTICK/审计字段且可回查；幂等/并发成立。
- 已在目标 Android 工业 PDA 验证扫码广播协议及网络异常恢复。
- 生产服务具备有效访问限制、生产写入开关、监控、回滚、最小权限。
- `AGENTS.md`、`requirements.md`、契约、字段映射和实际代码保持一致。

## 5. 不能视为测试通过的情况

- 只执行静态代码分析、只查 SQL 表头或看旧 APK 截图。
- 在仅含 Mock 的测试里证明“生产数据库可写”。
- 没有 Android workload 仍报告 APK build passed。
- 未执行请求重放/并发用例却仅通过 UI 按钮禁用声称幂等。
- 标签过滤测试仅覆盖 STA=1 而遗漏已明确允许的所有状态。
