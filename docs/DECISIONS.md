# StockCount 设计决策与待确认项（ADR 汇总）

> **2026-11-23 V1 决策基线。** 表内的“已确认”基于用户在历史会话中的明确要求；“设计采用”是为安全与可维护性作出的工程决策；“待确认”不是可擅自实现的授权。

## 1. 已确认业务决策

| ID | 决策 | 依据/后果 |
| --- | --- | --- |
| D-001 | **无应用内登录** | APK 不出现账号/密码/注册页；服务访问仍须控制 |
| D-002 | **支持正式/测试帐套切换** | `Production → sagex3.COB`，`Test → sagex3.XTEST`；用户明确了两 Schema 归属 |
| D-003 | **进入后展示当前帐套的全部已有盘点单** | 不按 `CUNSTA_0` 过滤列表；支持搜索/分页 |
| D-004 | **选择现有单据盘点，V1不创建单据** | 不编写 `AddXCOUTH` UI/API |
| D-005 | **V1不关闭盘点单** | 不编写 `CloseXCOUTH` UI/API |
| D-006 | **`XLABELDTL.STA_0` 不限制盘点** | 2026-11-20 的新规则**取代**先前 `STA_0 IN (1,7,8)`；包括4/9在内均不单因状态拒绝 |
| D-007 | **人工输入一次 STU 实盘数，同值保存 `XCOUTD.QTYSTU_0` 和 `XCOUTD.QTYPCU_0`** | **2026-11-23 用户明确补充：两列完全相等**；与标签当前 `QTY_0` / QR 原始 QT 分开 |
| D-008 | **先扫实际库位再扫箱码** | 没库位时先扫箱必须阻止并提示 |
| D-009 | **保存成功保留单号/名称/库位、清空当前箱表单** | 只有服务器确认保存成功才清 |
| D-010 | **所有 `XCOUTH.CUNSTA_0` 状态均允许提交（2026-11-25 更新）** | 状态仅供参考；包括已结束及未知状态；其他授权和校验保留 |
| D-011 | **.NET 10/C# 的 MAUI Android + ASP.NET Core API** | 后端统一访问 ERP/SQL，PDA 不直接连数据库 |

**D-012（2026-11-23）**：Windows 后端管理界面选用 **Tauri 2 + React/TypeScript + Rust + .NET 10 API Sidecar**，不使用 WPF。现场人员可从桌面 UI 读取/编辑 SQL Server 配置，DB/证书密码及设备密钥保存到 Windows Credential Manager；日志用 SQLite。PDA 自身可配置 API 地址/环境/设备密钥，但不可读取数据库账号/密码。此决策不代表 API 业务写入已经验收。

**D-013（2026-11-23，最新需求）**：**测试帐套 `XTEST` 和正式帐套 `COB` 的盘点 API 均允许写入 `XCOUTD`**，共用 POST 提交与 GET 幂等结果接口。Tauri 后端管理器提供两套分别可编辑的 `EnableTestWrites`/`EnableProductionWrites`，以及独立的 Test/Production Schema 核验开关；各自默认关闭，不互相继承确认结果。此决策替代“正式帐套永久禁止写入”的旧阶段约束，并不豁免现场 SQL 权限、ERP 触发器/ROWID/单位核对及生产审计要求。2026-11-23 本轮未连接现场 XTEST/COB 执行 INSERT，因此上线状态仍需验证。

## 2. 工程已采用的安全决策（非自动通过的业务规则）

| ID | 工程决策 | 原因 |
| --- | --- | --- |
| A-001 | 固定两环境 enum/Schema 白名单，不提供自由 Schema 输入 | 防止 SQL 注入、串库与误操作 |
| A-002 | 生产写入默认关闭，XTEST 受控联调后审批开启 | 降低 ERP 数据污染风险 |
| A-003 | 无登录情况下限制服务访问网络/受控设备 | 没有应用登录也要防未授权写入 |
| A-004 | 端到端请求 ID、可查询未知状态、幂等写入 | 防止断网重试/双 PDA 双写 |
| A-005 | 只读列表展示所有状态，`canSubmit` 与状态显示分离 | 避免把显示资格误当写权限 |
| A-006 | 原始数量与实盘数量分离；服务器重查标签和数量上下文 | 保持人工实盘的业务真实性 |
| A-007 | 第一期只做列表、扫描、设置和必要的异常处理 | 避免范围蔓延，减少学习成本 |

## 3. 未定规则与阻断等级

| ID | 级别 | 尚待确认的问题 | 在批准前的处理 |
| --- | --- | --- | --- |
| U-001 | **已确认** | 所有盘点单状态均可提交 | 不以状态拒绝写入；不修改表头状态 |
| U-002 | **生产写入阻断** | **两数量列同值已确定**；尚需确认 `PCUSTUCOE_0` / `PCU_0` 与这一规则在 Sage X3 服务中的兼容性 | XTEST 验证之前不能执行生产写入；不得将数值变成不同值 |
| U-003 | **生产写入阻断** | `ROWID/AUUID_0/UPDTICK_0`、审计时间与用户字段如何生成；是否经 X3 业务服务写入 | 不直接拼裸 INSERT |
| U-004 | **生产写入阻断** | 同单同箱重复是否禁止、合法复盘例外及授权机制 | 仅保留“建议同单去重”，先调查历史重复 |
| U-005 | P0 | 实盘数量是否可为0；PCS是否只能整数；负数/小数/超标签数的提示或限制 | Core 规则抽象并在联调前落实；不猜测 |
| U-006 | 已确认协议，待现场验收 | `LC.` 前缀由现场需求于 2026-11-24 确认；提取值后查 STOLOC.LOC_0 并核对表头站点/仓库 | 兼容纯库位值；真机和实际 SQL 数据仍待验收 |
| U-007 | P0 | PID 50 → BOXNUM 20、标签LOC 20 → 明细LOC 10 的超长场景如何处理 | 禁止截断，先显式拒绝 |
| U-008 | P0 | 工业 PDA 的真实型号、广播 Action/Extra/Android 版本 | Mock 开发后真机核验 |
| U-009 | P0 | 无登录服务访问控制、PDA审计标识与生产准入责任人 | 在部署前批准安全方案 |
| U-010 | P1 | 是否需要已盘记录列表、撤销/复盘、离线草稿加密 | V1 可先只读记录，修改操作后续批准 |
| U-011 | P1 | `ITMMASTER` 品名、规格在各站点/语言/物料下的关联唯一性 | 先只读核验；不能编造缺省值 |
| U-012 | P1 | 扫码是否支持所有 `PT/WO/SE/T` 变体，`PG` 含义 | 不当作所有代码路径都已验证 |

## 4. 实测而非规范的历史事实

- 正式 COB `XCOUTH` 曾实测 5 张 2026 年盘点单，测试 XTEST 11 张 2023—2024 年盘点单；其他业务时间点需重新查询，不应把历史统计硬编码成 API 数据。
- 测试 XTEST 11 单对 `XCOUTD` 的关联总条数为 **23,197**，10 单有明细、1 单无明细。
- 正式 COB `XCOUTD` 曾实测 22,936 条，`QTYPCU_0=QTYSTU_0` 且系数=1；**最新需求正式规定两数量列相等**，但不证明 `PCUSTUCOE_0` 可以永远写死为1。
- COB 有两组同单同箱历史重复，XTEST 所测 11 单均未发现同单重复；不能据此决定最终去重策略。
- XTEST 2023–2024 的旧界面“正常”对应表头 `CUNSTA_0` 不止一种码值，中文状态映射未确认。
- 旧 APK 在扫描后经 `GetPidData` 的 `QTY_0` 写数量，并非人工 STU 确认流程。**StockCount 与旧 APK 的数量策略不同**。

## 5. 决策变化工作流

用户给出新决定后，先更新本表（含日期和旧决定变化）→ 更新 `requirements.md` → 调整 API、字段映射/测试 → 变更源码。不能只改某份 AI 提示词而留下多个冲突业务版本。
