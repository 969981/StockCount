# 项目说明与开发协作指南

## 1. 项目定位

`StockCount` 是面向仓库盘点人员的 **C# / .NET 10 Android 工业 PDA + ASP.NET Core API**，读取既有 Sage X3 盘点单、扫码库位和箱标签，并将人工 STU 实盘数保存为盘点明细。

**不是** ERP 库存调整程序、不是盘点单管理后台、不是原 X3 PDA APK 的直接反编译移植，也与外协扫码作业 `OutsourceFlow` 为不同业务项目。

## 2. 用户与运行方式

- 目标操作：单手/物理扫码键连续扫描；界面大字号、固定单号/库位/提交区。
- **无应用内登录**；不对操作者显示登录页、注册页或角色管理。
- 设置页切换 `Production/COB` 或 `Test/XTEST`；测试建议默认，生产须明确提示与后端放行。
- 主页列出当前环境全部已有盘点单，选择一张后进入扫码；V1 不提供创建/关闭功能。

## 3. 主要页面

| 页面 | 功能 | V1 |
| --- | --- | --- |
| 盘点单列表 | 全量分页、搜索、刷新、日期/站点/仓库/状态展示、进入单据 | 必须 |
| 扫码盘点 | 扫库位→扫二维码→显示物料→手填STU→提交→下一箱 | 必须 |
| 设置 | 环境切换、API 状态、扫码配置 | 必须 |
| 已盘记录 | 分页只读，支持排查重复 | 可选 P1 |
| 登录/创建/关闭 | 以上功能均不出现 | 排除 |

## 4. 前端/后端职责边界

前端：显示/扫码/录入/草稿、环境选择、请求 ID 管理、提示反馈；**不直连 SQL**。

后端：环境白名单、SQL/ERP 查询、状态与字段校验、幂等和事务、审计/错误码；完整持久化必须通过经过验证的 X3 写入渠道。

不会因为无登录而删除服务端访问控制；服务应置于受控内网/VPN/可信设备网络并具独立的写入授权与审计。

## 5. 统一研发流程

1. 阅读 [AGENTS.md](../AGENTS.md) 和 [requirements.md](../requirements.md)。
2. 按 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) 领取单一前端或后端任务。
3. 先定义或复核 [API_CONTRACT.md](API_CONTRACT.md)，修改的 DTO 与两端同步。
4. 代码、测试、文档同 PR；描述所执行命令与真实输出。
5. 测试尽量使用合成数据、Mock 与只读 XTEST；写入测试须明确批准。
6. 正式环境启用写入前走 [TEST_PLAN.md](TEST_PLAN.md) 的发布门禁。

## 6. 项目完成定义

V1 只有在**无登录启动、环境隔离、全量列单、库位先扫、标签不按 STA 拦截、手填实盘数量、可靠幂等写入、异常恢复、真实 PDA 扫码、XTEST 联调和正式写入审批**均通过，才能标记“可上线”。文档提交本身不代表完成任何代码功能。

## 7. 文档维护策略

- 业务规则：`requirements.md` + `DECISIONS.md`；
- 组件、依赖、环境：`architecture.md` + `TECH_STACK.md`；
- SQL 字段与跨帐套差异：`DATABASE_MAPPING.md`；
- 外部行为：`API_CONTRACT.md`；
- 具体实现和验收：`IMPLEMENTATION_PLAN.md`、`TEST_PLAN.md`。
- 用户确认新规则时统一更新相关文件，不继续引用被废弃的标签 STA 白名单。
